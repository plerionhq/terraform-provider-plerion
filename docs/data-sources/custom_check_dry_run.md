# plerion_custom_check_dry_run (Data Source)

Runs a custom check against the current assets of one integration and returns the findings it would produce, without saving them. Use it to preview a new or changed policy before you apply it.

The check does not need to be saved first. A new dry run starts every time Terraform reads this data source, which is usually on each plan. Reading fails if the policy cannot be evaluated, so a broken policy stops the plan.

## Example usage

```terraform
variable "production_integration_id" {
  description = "The Plerion integration to preview the policy against."
  type        = string
}

# Preview the findings a check would produce in one integration before
# saving it. Reading the data source fails if the policy cannot be evaluated.
data "plerion_custom_check_dry_run" "github_oidc_roles" {
  integration_id = var.production_integration_id

  target = {
    asset_type = "AWS::IAM::Role"
    scope      = "batch"
  }

  defaults = {
    severity_level = "HIGH"
    message        = "The role trusts GitHub OIDC without limiting which repository can assume it."
  }

  body = file("${path.module}/policies/github-oidc-roles.rego")
}

# Stop the plan if the policy would flag more roles than expected.
check "github_oidc_roles_preview" {
  assert {
    condition     = data.plerion_custom_check_dry_run.github_oidc_roles.total_findings <= 5
    error_message = "The policy would flag ${data.plerion_custom_check_dry_run.github_oidc_roles.total_findings} roles. Review the policy before applying it."
  }
}

output "flagged_roles" {
  value = [for finding in jsondecode(data.plerion_custom_check_dry_run.github_oidc_roles.findings) : finding.assetId]
}
```

## Check a policy before Terraform applies it

Terraform reads a data source during the plan only when nothing the data source refers to is waiting to change. If the dry run refers to a `plerion_custom_check` resource that has changes, Terraform waits until the apply to read it, which is after the check has already changed.

To preview a change during the plan, keep the check's settings in `locals` and give the same values to the resource and to the dry run. A `precondition` on the resource then stops the apply when the preview is not what you expect.

```terraform
locals {
  github_oidc_roles = {
    target = {
      asset_type = "AWS::IAM::Role"
      scope      = "batch"
    }
    defaults = {
      severity_level = "HIGH"
      message        = "The role trusts GitHub OIDC without limiting which repository can assume it."
    }
    body = file("${path.module}/policies/github-oidc-roles.rego")
  }
}

data "plerion_custom_check_dry_run" "github_oidc_roles_gate" {
  integration_id = var.production_integration_id
  target         = local.github_oidc_roles.target
  defaults       = local.github_oidc_roles.defaults
  body           = local.github_oidc_roles.body
}

resource "plerion_custom_check" "github_oidc_roles" {
  slug     = "github-oidc-roles-must-pin-a-repository"
  title    = "GitHub OIDC roles must pin a repository"
  target   = local.github_oidc_roles.target
  defaults = local.github_oidc_roles.defaults
  body     = local.github_oidc_roles.body

  lifecycle {
    precondition {
      condition     = data.plerion_custom_check_dry_run.github_oidc_roles_gate.total_findings <= 5
      error_message = "The policy would flag more than 5 roles. Review it before applying."
    }
  }
}
```

## Which assets a dry run sees

A dry run evaluates the assets Plerion collected in its most recent scan of the integration. An integration that has not been scanned yet has no assets, so the dry run succeeds with no findings.
