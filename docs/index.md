# Plerion Provider

Use the Plerion provider to manage [Plerion](https://www.plerion.com) resources through the Plerion customer API.

The provider manages two things:

- **Custom checks.** A custom check is a rego policy that Plerion evaluates against the assets it collects from your cloud integrations. Keeping checks in Terraform lets you review policy changes in pull requests, preview their findings before they go live, and roll them out through your existing pipeline.
- **AWS onboarding.** Connect AWS accounts to Plerion, and set up the service accounts Plerion's workload scanners run in, in the same configuration that creates their IAM roles. Plerion assumes each role with your tenant's external ID before it saves anything.

## Example usage

```terraform
terraform {
  required_providers {
    plerion = {
      source  = "plerionhq/plerion"
      version = "~> 0.1"
    }
  }
}

# Reads the API key from the PLERION_API_KEY environment variable.
provider "plerion" {
  api_url = "https://us1.api.plerion.com"
}
```

## Authentication

The provider authenticates with a tenant API key. Create one in the Plerion app under **Settings > API Keys**.

Treat the key like a password. Set it with the `PLERION_API_KEY` environment variable, or pass it in from a variable marked `sensitive`, rather than writing it in your configuration.

The key's role decides what the provider can do:

- Managing checks needs permission to read and change custom checks.
- Dry runs also need permission to read assets in the integration they run against.
- Connecting AWS accounts needs permission to change integrations and service accounts. The `plerion_tenant` data source also needs permission to change integrations, because it reads the external ID.

## Regions

API keys only work in the region where they were created. Set `api_url`, or the `PLERION_API_URL` environment variable, to the address of your region. The host on its own, such as `au.api.plerion.com`, works too.

| Region | `api_url` |
| --- | --- |
| Australia | `https://au.api.plerion.com` (the default) |
| India | `https://in1.api.plerion.com` |
| Singapore | `https://sg1.api.plerion.com` |
| South Korea | `https://kr1.api.plerion.com` |
| United States | `https://us1.api.plerion.com` |

## Retries

The provider retries a request when the API asks it to slow down. It also retries server errors on reads, deletes, custom check updates and service account region updates, which are safe to repeat. It does not retry a failed create, because that could create the record twice, or a failed change to an AWS integration or service account.
