# plerion_aws_service_account (Resource)

An AWS account you run Plerion's workload scanners in. Plerion assumes `control_plane_role_arn` before it saves anything. Add the network for each region with `plerion_aws_service_account_region`.

## Example usage

```terraform
# The control-plane role must carry the tag RolePurpose = "PlerionAccess";
# Plerion only assumes roles with it.
resource "plerion_aws_service_account" "this" {
  control_plane_role_arn = aws_iam_role.plerion_control_plane.arn
  instance_profile_arn   = aws_iam_instance_profile.plerion_appliance.arn
  name                   = "workload-scanners"
}
```

## Approval

Plerion holds a service account from an AWS organization your tenant hasn't connected before until someone approves it in the Plerion console. `terraform apply` doesn't wait for that: the service account is created with `status = "pending_approval"` and Terraform prints a warning. Plerion refuses a [`plerion_aws_service_account_region`](aws_service_account_region.md) for it until it is approved.

## Turning it on and off

Turning a service account on and off stays in the Plerion console, so `enabled` is read-only here.

## New IAM roles

AWS can take a minute or two before it lets Plerion assume a role created in the same apply. The provider retries for up to two minutes.

## Schema

### Required

- `control_plane_role_arn` (String) Role Plerion assumes to launch and manage scanners. The role must carry the tag `RolePurpose = PlerionAccess`. Pointing it at another AWS account replaces the service account.
- `instance_profile_arn` (String) Instance profile the scanners run with. Must be in the same account as the role.

### Optional

- `name` (String) Display name. Defaults to the account's IAM alias, or the account id.
- `template_version` (String) Version of the Plerion template this was made from, so Plerion can tell when it's out of date. The Plerion templates set it. Once set it is kept, even if you remove it from the configuration.

### Read-Only

- `account_id` (String) AWS account id, taken from `control_plane_role_arn`.
- `aws_organization_id` (String) AWS organization the account belongs to, as Plerion read it.
- `enabled` (Boolean) Whether Plerion scans through this service account. Turned on and off in the Plerion console.
- `id` (String) Same as `account_id`.
- `status` (String) `active`, or `pending_approval` while Plerion waits for someone to approve an account from an AWS organization the tenant hasn't seen before.

## Import

Import a service account by its AWS account ID.

```shell
terraform import plerion_aws_service_account.this 123456789012
```
