# plerion_custom_check (Resource)

Manages a custom check. A custom check is a rego policy that Plerion evaluates against the assets it collects from your integrations. The policy reports assets as passed or failed, and each report becomes a finding.

Plerion runs a check after each scan, and again straight after the check is created or changed.

## Example usage

```terraform
resource "plerion_custom_check" "github_oidc_roles" {
  slug        = "github-oidc-roles-must-pin-a-repository"
  title       = "GitHub OIDC roles must pin a repository"
  description = "Flags IAM roles that any GitHub repository can assume, because their trust policy has no repository condition."

  target = {
    asset_type = "AWS::IAM::Role"
    scope      = "batch"
  }

  defaults = {
    severity_level = "HIGH"
    message        = "The role trusts GitHub OIDC without limiting which repository can assume it."
    remediation    = "Add a StringLike condition on token.actions.githubusercontent.com:sub that names your repository."
    meta = jsonencode({
      owner = "platform-security"
    })
  }

  body = file("${path.module}/policies/github-oidc-roles.rego")
}
```

The policy file, `policies/github-oidc-roles.rego`:

```rego
package custom

# Reports every role whose trust policy lets GitHub Actions assume it without
# naming a repository. Roles that pass are left out of the result.
default result := []

result := [{"id": role.id, "status": "FAILED"} |
	role := input.assets[_]
	statement := role.data.AssumeRolePolicyDocument.Statement[_]
	statement.Effect == "Allow"
	contains(statement.Principal.Federated, "token.actions.githubusercontent.com")
	not statement.Condition.StringLike["token.actions.githubusercontent.com:sub"]
]
```

## Writing the policy

A policy must declare `package custom` and define a rule named `result`. Plerion evaluates the rule and reads its value as a list of verdicts, one for each asset you want to report on.

### What the policy receives

| Field | Contents |
| --- | --- |
| `input.assets` | The assets of the `target` asset type. With `scope = "batch"`, this is one chunk of those assets. With `scope = "all"`, it is every asset of the type. Each asset has an `id`, and the configuration Plerion collected from the cloud provider is under `data`. |
| `input.additionalAssets` | An object keyed by asset type that holds every asset of each type listed in `additional_assets`, for example `input.additionalAssets["AWS::IAM::Role"]`. |
| `input.context` | The `tenantId`, `organizationId` and `integrationId` the check is running for. |

### What the policy returns

Each verdict in `result` is an object with these fields.

| Field | Required | Description |
| --- | --- | --- |
| `id` | Yes | The `id` of an asset in `input.assets`. |
| `status` | Yes | `FAILED` or `PASSED`. |
| `severityLevel` | No | Replaces `defaults.severity_level` for this finding. |
| `message` | No | Replaces `defaults.message` for this finding. |
| `informational` | No | Replaces `defaults.informational` for this finding. |
| `remediation` | No | Replaces `defaults.remediation` for this finding. Used on failed findings only. |
| `meta` | No | An object merged over `defaults.meta` for this finding. |

Every verdict becomes a finding, so an asset left out of `result` has no finding at all. Return a `PASSED` verdict for an asset when you want it to show as passed.

If any verdict has another `status`, or names an asset that is not in `input.assets`, Plerion rejects the whole evaluation.

Preview a policy before you apply it with the [`plerion_custom_check_dry_run`](../data-sources/custom_check_dry_run.md) data source.

## When checks run

Plerion runs a check after each scan of your integrations. It also runs a check straight after the check is created or changed, so a change you apply shows up in findings without waiting for the next scan.

A check only runs against integrations from the cloud provider its `target` asset type belongs to. For example, a check on `AWS::IAM::Role` runs against your AWS integrations only.

## Schema

### Required

- `body` (String) The rego policy. It must declare `package custom` and define a `result` rule that returns a list of verdicts, one for each asset to report on. Load it from a file with `file("${path.module}/policies/my-check.rego")` to keep the policy readable.
- `defaults` (Attributes) Values applied to each finding when the policy's result does not set them. (see [below for nested schema](#nestedatt--defaults))
- `slug` (String) A name for the check that is unique within the tenant. Use lowercase letters, numbers and hyphens, up to 128 characters. You can change it later without replacing the check.
- `target` (Attributes) The asset type the check evaluates. Each asset of this type is passed to the policy in `input.assets`. (see [below for nested schema](#nestedatt--target))
- `title` (String) The title shown for the check in the Plerion app. Up to 256 characters.

- `type` (String) The policy language. The only supported value is `rego`, which is the default.

## Import

Import a custom check by its ID or by its slug. With an `import` block:

```terraform
import {
  to = plerion_custom_check.github_oidc_roles
  id = "github-oidc-roles-must-pin-a-repository"
}
```

With the `terraform import` command:

```shell
# Import a custom check by its ID.
terraform import plerion_custom_check.github_oidc_roles 3f2a9c4e-8b1d-4c7a-9e6f-2d5b8a1c4e7f

# Or import it by its slug.
terraform import plerion_custom_check.github_oidc_roles github-oidc-roles-must-pin-a-repository
```
